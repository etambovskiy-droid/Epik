# Реалізація ізоляції Демо-режиму (Default Deny Sandbox) та Захисту Токенів Власника (BYOK Zero Token Spend)

## 1. Архітектура Демо-режиму (Default Deny Whitelist)
- **Принцип Білого Списку**: Для користувачів з `isDemo === true` дозволено **ВИКЛЮЧНО** `VIEW_SAMPLE_3_ROWS` (перегляд 3 зразкових рядків офіційних категорій Епіцентру).
- **Майбутня сумісність**: Будь-яка нова функція, яка додаватиметься до системи у майбутньому (новий ключ у системі прав), за замовчуванням блокується (`false`) для демо-користувача без потреби ручного оновлення кожного компонента.
- **Повна ізоляція операцій у Демо**:
  - 🔒 Завантаження власних Excel-шаблонів (drag & drop та вибір файлу) — заблоковано.
  - 🔒 Завантаження фотографій та ZIP-архівів — заблоковано.
  - 🔒 Завантаження власних довідників характеристик — заблоковано.
  - 🔒 Завантаження та парсинг XML/YML фідів — заблоковано.
  - 🔒 Конвертер фідів Prom / Rozetka — заблоковано.
  - 🔒 ШІ-Фотостудія (Gemini Nano Banana 2.1) — заблоковано.
  - 🔒 Google Search Grounding (пошук характеристик) — заблоковано.
  - 🔒 ШІ-Консультант (Gemini) — заблоковано.
  - 🔒 Додавання нових магазинів / кабінетів селера — заблоковано.
  - 🔒 Історія партій обробки — заблоковано.
  - 🔒 Керування API-ключами (AI Studio та Merchant API) — заблоковано.
  - 🔒 Експорт заповнених Excel, CSV або вибраних рядків — заблоковано.
- **Інтерфейс інформування (Без window.alert)**:
  - Створено фірмове модальне вікно `DemoRestrictionModal` з поясненням обмеження та переваг кабінету мерчанта.
  - 1-клік CTA кнопка «Створити кабінет мерчанта», яка виходить із демо-режиму та відкриває модальне вікно реєстрації селера.
  - Усі системні виклики `window.alert()` повністю вилучені з кодової бази.

## 2. Політика Захисту Токенів Власника (BYOK — Zero Owner Token Spend)
- **Суворе відхилення без власного ключа**:
  - Вилучено всі небезпечні фолбеки до `'server-managed'` або використання `process.env.GEMINI_API_KEY` для операцій користувачів.
  - Серверний middleware `/api/gemini` автоматично валідує заголовок `x-gemini-api-key` або поле `apiKey` у тілі запиту.
  - Якщо ключ клієнта відсутній або дорівнює `'server-managed'`, сервер негайно повертає `401 Unauthorized` з кодом `API_KEY_REQUIRED` без звернення до Gemini API.
  - Клієнтський шар `geminiClientDirect` локально перевіряє наявність ключа через `hasUserApiKey()` перед відправкою запиту і, у разі відсутності, викликає подію `epic_ai_missing_key_warning` з відкриттям вікна додавання власного ключа Google AI Studio.
  - Жоден користувацький запит (генерація назв, збагачення характеристик, XML-мапінг, ШІ-фото, чат, пошук у Google) **не витрачає квоти або кошти власника платформи**.
